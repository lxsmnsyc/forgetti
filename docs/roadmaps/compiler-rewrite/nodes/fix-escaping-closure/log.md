# Log: fix-escaping-closure

- Base `a00b9fa` (batch/compiler-rewrite). `pnpm --filter compare table --set heldout --case form_validation`: next bails `SignupForm` as `escaping-closure` (1/2 compiled, 1 bailout). Work React 72 against React Compiler 25.
- Cause found with `analyzeOwnership`: the bailout range is `text('firstName', 'First name')`. The local helper `text` is a closure. `evaluateCall` in `ownership/walk.ts` treats every call of a fresh closure as a mutation of what it captures. The second call, `text('lastName', ...)`, counts as a mutation after the first call let the closure escape, so the group stops being frozen and the unit bails.
- Smallest repro (bails on base, compiles on the branch): `tag = (x) => <i>{x}</i>; row = (x, y) => <b>{tag(x)}{a}{y}</b>; return <div>{row(1, b)}{row(2, b)}</div>`. Neither helper changes anything it captures, so each call is a read and the group is frozen.
- Fix 1, `ownership/walk.ts`: a call of a fresh closure mutates its captures only when `isMutatingValue` holds for the callee (its body changes a captured fresh value). Arguments of the call are still marked as mutated, since the closure may write through its parameter or keep it.
- After fix 1 `form_validation` compiled, but work stayed at 61: `errors = validateAll(...)` was not cached. `isResultReadOnly` refused it because `Object.keys(errors)` hands it to a call. Fix 2, `plan/baseline.ts`: `Object.keys(x)` on the global `Object` is a read-only use.
- Probe `HelperTick` found a DIFF after fix 1: a module `let` that render assigns (`tick += 1`) counted as a stable outer in `getBindingDeps`, so a closure reading it was cached with no inputs and the block that calls it never ran again. Base hid this behind the bailout. Fix 3, `plan/baseline.ts`: `isStableOuter` is false for a binding that any code writes.
- Tuning case `escaping_closure`: scenarios were cut to what next can match. `Rows` with `one_name` or `new_names` and `Pair` with `new_left` lose to React Compiler because a block that calls a local helper is keyed on all its inputs, not per call. That is a planner cost, not a soundness need.
- Probes are in `probes/` (not a corpus set, they put next above React Compiler on mutation shapes by design). Run by copying to `benchmarks/corpus/tuning/escaping_probe/` and `pnpm --filter compare table --set tuning --case escaping_probe`.
